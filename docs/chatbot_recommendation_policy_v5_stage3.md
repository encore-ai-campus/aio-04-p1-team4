# 챗봇 추천 정책 v5 — 3단계: 식당 후속 질문

- 대상 프로젝트: C:\temp_resolved
- 앞선 구현: [1단계 필터](chatbot_recommendation_policy_v5_stage1.md), [2단계 메뉴·식당 흐름](chatbot_recommendation_policy_v5_stage2.md)
- 기존 문서는 기록으로 유지하며, 이번 문서는 3단계 변경분을 설명합니다.

## 1. 무엇이 달라졌나

예전에는 식당 ID만 기억하고 가격 질문 때 DB에서 같은 대표 메뉴의 가장 싼 상품을 다시 골랐습니다. 그 사이 상품이 추가되거나 가격이 바뀌면 앞서 보여준 상품과 다른 가격으로 답할 수 있었습니다.

이제 추천 답변에 실제 표시한 식당 순서와 식당명·상품 ID·대표 메뉴 ID·상품명·가격을 세션에 복사합니다. 이 복사본을 '표시 당시 기록'이라고 합니다. 최대 3곳이며 배열의 첫 항목이 첫 번째 식당입니다.

| 질문 | 답변에 사용하는 정보 |
|---|---|
| 첫 번째/두 번째/세 번째 식당 가격은? | 해당 순서에서 표시했던 상품명과 당시 가격 |
| 그 식당 주소 알려줘 | 대상 식당의 DB 주소 |
| 지금 영업 중이야? | 대상 식당의 저장된 시간표와 질문 시점 한국 시간 |
| 왜 추천했어? | 마지막 추천이 메뉴인지 식당인지와 추천 당시 조건 |

가격은 `앞서 표시한 가격 기준`이라고 명시합니다. 최신 매장 가격을 보장하는 뜻은 아닙니다. DB 가격이 변경되었으면 식당 목록을 다시 조회한 뒤 그 새 표시 가격으로 질문할 수 있습니다. 다른 저렴한 상품으로 자동 바꾸지 않습니다.

## 2. 세부 답변 규칙

- 표시 가격이 NULL이면 `해당 식당의 메뉴 가격 확인 불가`.
- 표시 가격이 예산을 초과하면 `예산에 적합하지 않음`. 정상 추천 필터는 예산 초과 상품을 이미 제외하므로 이 경우는 방어 처리입니다. 예산을 바꾸면 과거 목록 자체를 무효화합니다.
- 주소가 없으면 `주소가 명시되어 있지 않습니다`.
- 시간표가 없거나 오늘 구간이 불완전하면 `영업시간 미기재로 인해 알 수 없습니다`.
- 영업 중/종료는 매 질문 시 계산합니다. 추천 때의 open 상태를 그대로 재사용하지 않습니다. 추천 필터와 동일한 휴무·브레이크 타임·익일 종료 판정을 사용합니다.
- 메뉴 추천 이유는 위치·반경·음식 종류·예산·점심시간을 줄별로 보여준 뒤 `앞서 입력해주신 조건에 부합하는 메뉴를 추천드렸습니다.`를 표시합니다.
- 식당 추천 이유는 `현재 위치를 기반으로 추천한 메뉴를 판매하는 식당을 추천드렸습니다.`를 표시합니다.
- 점심시간은 입력 조건 안내이며 이동·식사시간을 계산해 보장하지는 않습니다. 가격·영업시간 미확인 추천도 기존 확인 문구를 유지합니다.

## 3. 모호한 지칭과 오래된 목록

1. 첫째~셋째, 첫 번째~세 번째, 1번~3번 등의 순서는 서버가 표시 기록으로 확정합니다. Groq가 다른 식당 ID를 선택해도 순서 표현을 우선합니다.
2. 여러 식당을 보여준 직후 `그 식당 주소`처럼 대상이 불명확하면 번호나 이름을 확인합니다. Groq 지침에도 모호하면 확인하도록 명시합니다.
3. `두 번째 식당 주소`처럼 하나를 지목한 이후에는 `그 식당 가격`을 방금 지목한 식당으로 이어갈 수 있습니다.
4. 네 번째처럼 표시 목록에 없는 번호를 임의 매칭하지 않습니다.
5. 식당 DB 행이 삭제되어도 저장된 표시 순서를 당기지 않습니다. 가격은 당시 기록으로 답할 수 있지만 주소·시간표의 식당 행을 찾지 못하면 안내합니다.
6. 새 메뉴 추천, 재추천, 식당 재조회 시 표시 목록을 교체합니다. 예산·음식 종류·위치·반경 변경 시 과거 목록과 추천 이유 문맥을 무효화합니다.

최근 대화는 기존처럼 10턴만 유지합니다. 현재 표시 목록은 대화 턴 목록과 별도 보관하여 오래된 질문이 대화창 기억 범위에서 빠져도 사용할 수 있습니다. 현재 메모리 세션이므로 서버 재시작·세션 만료 시에는 다시 추천받아야 합니다.

## 5. 직접 검증 방법

서버 실행 창에서 Ctrl+C로 기존 프로세스를 종료한 뒤 재시작합니다.

```powershell
cd C:\temp_resolved
.\run.ps1
```

브라우저 http://127.0.0.1:8000/ai 를 열고 Ctrl+F5로 새로고침합니다. 위치·반경·예산·음식 종류·점심 종료 시각을 설정합니다.

### A. 메뉴 추천 이유

1. `메뉴 추천해줘`를 입력합니다.
2. `왜 추천했어?`를 입력합니다.
3. 추천 당시 조건이 줄별로 나오고 정해진 메뉴 추천 이유 문구가 붙는지 확인합니다.

### B. 식당 순서와 가격

1. `이 메뉴 파는 식당 알려줘`를 입력합니다.
2. 표시된 목록의 이름·메뉴·가격을 확인합니다.
3. `첫 번째 식당 가격은?`, `두 번째 식당 가격은?`, `세 번째 식당 가격은?`를 차례로 입력합니다.
4. 각 가격이 해당 줄의 상품명·금액과 일치하며 `앞서 표시한 가격 기준` 안내가 나오는지 확인합니다. 세 곳이 없다면 존재하는 번호만 답하고 없는 번호는 확인을 요청해야 합니다.
5. `왜 추천했어?`를 입력하면 식당 추천 이유 문구가 나와야 합니다.

### C. 주소·영업 상태·대상 확인

1. 목록 조회 직후 여러 식당이 있는 상태에서 `그 식당 주소 알려줘`라고 하면 대상을 확인해야 합니다.
2. `두 번째 식당 주소 알려줘`처럼 하나를 지정합니다. DB 주소가 표시되는지 확인합니다.
3. 이어서 `그 식당 가격은?`이라고 하면 방금 지목한 두 번째 식당의 표시 가격이 나와야 합니다.
4. `지금 영업 중이야?`로 시간표 기반 상태를 확인합니다. 미기재 시 정해진 미확인 문구가 나와야 합니다.

### D. 예전 목록 무효화

1. 식당을 추천받은 뒤 `메뉴 추천해줘` 또는 `다른 메뉴 추천해줘`를 입력합니다.
2. 식당을 다시 조회하지 않은 상태에서 `첫 번째 식당 가격은?`을 묻습니다.
3. 이전 식당 가격을 재사용하지 않고 식당 재조회/대상 확인을 안내해야 합니다.
4. 홈에서 반경·예산·음식 종류 또는 위치를 바꾼 후에도 이전 식당에 대한 질문이 그대로 답변되지 않는지 확인합니다.

브라우저 개발자 도구 Console에서 다음 요청으로 표시 기록을 볼 수 있습니다. 식당 목록을 조회한 직후 실행합니다.

```javascript
fetch('/api/chat/session').then(r => r.json()).then(console.log)
```

displayed_restaurants 배열의 restaurant_id, product_id, menu_name, price를 표시 목록과 비교합니다. last_recommendation_kind는 menu 또는 restaurant입니다. 이 API는 현재 브라우저 세션만 조회합니다.

실제 DB에 세 곳 또는 누락 사례가 없다면 아래 테스트로 확인할 수 있습니다. 검증을 위해 실제 DB를 수정할 필요는 없습니다.
