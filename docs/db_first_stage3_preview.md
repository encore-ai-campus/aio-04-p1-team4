## 식당 식별과 매칭

확정 카카오 ID → 네이버 ID → 정리한 식당명·주소 순으로 식별한다. 내부 UUID는 식별 키에서 결정적으로 생성해 같은 입력의 재실행 결과가 동일하도록 했다. 향후 기존 Supabase 데이터가 있으면 외부 ID로 먼저 찾아 그 DB의 기존 UUID를 재사용해야 한다.

확정 매칭 264건이 모두 원본 식당과 연결됐다. 확정 매칭의 고유 카카오 ID가 254개이므로 동일 카카오 ID를 가리키는 원본 식당을 병합했다. 기존 원본 ID와 확정 매칭 ID의 충돌은 없었다. 최종 예정 식당의 카카오 ID와 네이버 ID에 중복이 없는지 확인했다.

review 197건과 not_found 123건은 매칭 이력에 그대로 남겼다. review의 카카오 후보는 확정 ID로 사용하지 않았다. resolution_report 584건은 확정·미해결 목록을 합친 결과와 일치하는지 대조했으며 식당으로 중복 적재하지 않았다. matching CSV의 distance_m은 사용자 출발점 거리로 사용하지 않았다.

## 메뉴와 가격

원본 상품명은 보존하고 정규화명은 Unicode NFC·대소문자·공백만 정리했다. 세트·인분·크기가 다른 상품을 부분 문자열로 합치지 않았다. 같은 식당·상품명인데 가격이 다른 13개 그룹은 reviews.csv에서 검토한다.

가격 값이 있으면 양수 원화 정수인지 확인한다. 값이 없고 원문에 시가·변동이 있으면 variable, 그 외에는 missing으로 저장한다. 빈 값을 0원으로 채우지 않았다. 판매 상태는 원본 품절 표기가 비어 있어 unknown이며 현재 판매를 보장하지 않는다. 영업시간은 원본에 없으므로 생성하지 않았다.

## 대표 메뉴 연결 범위와 검토 사항

현재 seed.py의 대표 메뉴 10종을 초기 초안으로 사용했지만 설명·기준가격은 복사하지 않았다. 대표 메뉴 이름과 정확히 일치하는 상품 및 자장면→짜장면, 돈까스→돈가스만 연결했다. 된장찌개 항목에 남아 있는 과거 두부덮밥 별칭처럼 의미가 다른 기존 별칭은 복사하지 않았다. 세트·다인·추가·토핑·주류 표현은 자동 연결에서 제외했다.

402건 연결은 전체 식사 메뉴 분류가 끝났다는 의미가 아니다. 제육볶음·육개장·볶음밥·물냉면·비빔냉면·부대찌개·순두부찌개 등의 대표 메뉴 확장 후보가 남아 있다. 공기밥·주류·음료도 함께 존재하므로 미연결 상품 전체를 추첨 후보로 삼으면 안 된다. 정확한 상품명 일치만으로 피자 등의 1인분 적합성이 검증되는 것도 아니다.

미연결 상품은 DB 보존 가능 자료지만 menu_catalog_id가 NULL이므로 자동 추첨에서는 제외된다. 적재 승인 전에 대표 메뉴 확장과 1인 식사 적합성 검토를 먼저 진행하는 것을 권장한다. 기준가격은 대표 메뉴에 넣지 않고 실제 상품 가격으로만 예산을 판정한다.

## 분류 검토

서비스 분류로 매핑되지 않은 원본 값은 파리바게뜨·식껍·제과,베이커리·토스트 4개다. 현재 예정 자료는 기타로 표시하고 검토 목록에 남겼다. 원문은 category_name에 보존한다. 검토 없이 카페·고기 등으로 추측해서 확정하지 않았다.
