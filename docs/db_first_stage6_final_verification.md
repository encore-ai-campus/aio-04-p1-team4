# LunchRun DB 중심 전환 및 최종 점검 기록

작성일: 2026-11-13. 작업 대상: `C:\temp_resolved`.

## 최종 흐름

홈 위치·조건 입력 → DB 메뉴 후보 조회 → 게임 또는 AI로 메뉴 결정 → DB 식당 조회 → 카카오 지도 표시 순서다. 홈 조건 화면의 실제 경로는 `/#conditions`이며 `/conditions`도 같은 화면으로 연결한다. 지도에서 뒤로 가면 게임, 다시 뒤로 가면 이전 홈 화면으로 이동한다.

추천 데이터는 Supabase PostgreSQL의 대소문자를 구분하는 `"Lunchrun"` 스키마에서 조회한다. Groq는 의도·대상·조건 변경안을 해석하고, 메뉴·가격·식당 사실 답변은 서버가 DB 결과로 작성한다. 카카오 식당 검색이나 Playwright 수집은 일반 추천 요청에서 실행하지 않는다. 위치 선택을 위한 Geolocation·주소 검색, 카카오 지도 SDK와 길찾기는 유지한다.

## 공통 추천 기준

`app/db_recommendations.py`가 홈·게임·AI·지도의 공통 판정을 담당한다.

- 활성 대표 메뉴에 `menu.menu_catalog_id`로 확정 연결한 상품만 사용한다.
- 실제 표시 가격이 확인되고 예산 이내인 상품을 조회한다. seed의 `price_hint`나 상품명 부분 일치로 보충하지 않는다.
- 위치·직선 반경·매장 업종, 메뉴·영업시간 수집 성공 상태, 저장된 한국 시간표와 휴무를 확인한다.
- 품절·폐업 확인 데이터는 제외한다. 판매 상태 미확인은 경고를 표시한다.
- 인분 미확인은 표시 가격 기준 후보로 허용하고 홈·게임·AI·지도에 미확인 안내를 표시한다. 인원수로 나누어 1인분 가격을 추정하지 않는다.
- 후보가 없으면 조건 변경을 안내한다. DB 미연결 상품과 검토 대상은 보존하되 추천에서 제외한다.

## 최종 점검에서 수정한 내용

### AI 문맥 무효화

예산·업종·위치·반경 또는 명시한 선택 메뉴가 바뀌면 이전 추천 식당을 Groq의 현재 대상 목록에서 제거한다. 서버에 저장한 식당·선택 메뉴·대기 중 변경 문맥도 맞춰 초기화한다. 현재 문맥에 없는 식당의 상세 질문은 재조회를 안내한다. 재추천 결과가 없으면 서버 세션의 과거 선택 메뉴도 지운다.

### 실행 준비 검사

DB 조회 추천에는 Chromium이 필요하지 않으므로 `playwright_chromium`을 선택적 진단으로 바꿨다. `recommendation_source=database`와 `optional_checks`를 응답한다. 브라우저 설치 확인은 여전히 수집 작업·브라우저 테스트를 위한 정보로 제공하며 DB 연결·활성 카탈로그·필수 키 검사는 유지한다.

### 코드와 테스트 정리

사용하지 않는 카탈로그 부분 일치·기준가격 대체용 보조 코드를 제거하고 ORM 설명을 현재 FK 기반 구조에 맞췄다. 외부 검색 후 수집을 기대하던 API 테스트는 사전 적재 DB 조회와 무수정 조건을 검증하도록 갱신했다. SQLite 테스트는 격리된 ORM 검증용이며 PostgreSQL 전용 마이그레이션과 구분한다. 기존 SQLite 이력 검사는 0002까지의 보존 동작을 검증한다.

삭제된 화면 모듈을 참조하던 UI 테스트는 현재 `state.js`, `chat.js`, `location-picker.js`, 지도 겹침·경로 모듈을 대상으로 재작성했다. 실제 Chromium 통합 검사로 화면·게임·지도·AI 흐름을 함께 확인한다. 위치 변경 테스트에는 새 위치마다 실제 식당 상품을 준비하여 후보가 있다는 가정을 명시했다.

### 문서

README의 앞부분에 Uvicorn과 Node 게임 서버 실행 방법을 배치했다. 연결 변수 우선순위, Lunchrun 스키마, FK 관계, 데이터 수량, 별도 수집 작업, 인분 미확인 정책과 현재 프롬프트 버전을 갱신했다. 전환 전 문서는 참고 이력으로 구분했다.
