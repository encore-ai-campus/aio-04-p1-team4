# 음식 종류와 업태 연결

기준일: 2026-11-16. 분류 정의는 `app/food_types.py`, 추천 조건 적용은 `app/db_recommendations.py`를 따른다.

## 화면 선택지와 허용 업태

| 화면 선택지 | 허용 업태 |
| :---: | :---: |
| 전체 | 업태 제한 없음 |
| 한식 | 한식 |
| 중식 | 중국식, 중식 |
| 일식/회 | 일식, 횟집 |
| 양식 | 경양식, 패밀리레스트랑, 양식 |
| 분식 | 분식 |
| 패스트푸드 | 패스트푸드 |
| 치킨 | 통닭(치킨), 호프/통닭, 치킨 |
| 도시락/구내식당 | 김밥(도시락), 도시락, 구내식당 |
| 뷔페식 | 뷔페식, 뷔페 |
| 냉면 | 냉면집 |
| 고기 | 식육(숯불구이) |
| 카페/빵 | 까페, 카페 |
| 술집 | 감성주점, 호프/통닭, 라이브카페, 정종/대포집/소주방, 술집 |
| 기타 | 기타, 외국음식전문점(인도,태국등), 퓨전요리 |

화면 선택지는 `전체`를 포함한 15개다. `menu_catalog.cuisine`에는 `전체`를 제외한 14개 값만 저장한다. 채식·맵기는 요청 조건과 추천 필터에 포함하지 않는다.

## 추천에 적용되는 기준

1. 활성 대표 메뉴와 FK로 연결된 실제 식당 상품을 DB에서 조회한다.
2. 음식 종류는 `restaurant.cuisine`을 우선 사용하고, 값이 없으면 `restaurant.category_name`을 사용한다.
3. 업태 문자열을 `>`로 나누고 맨 앞의 `음식점`을 제거한 뒤 첫 분류를 위 표와 비교한다. `한식 > 육류,고기`는 한식이며 고기로 자동 분류하지 않는다.
4. `호프/통닭`처럼 여러 선택지에 포함된 업태는 각 선택지에서 허용한다. 표에 없는 업태를 임의로 `기타`에 넣지 않는다.
5. `전체`는 업태 검사만 생략한다. 반경·가격·영업 상태 등의 공통 조건은 계속 적용한다.

대표 메뉴의 저장 분류와 식당 업태는 별개다. 도시락집의 비빔밥처럼 서로 다를 수 있으므로, 응답의 메뉴 `cuisine`이 선택한 식당 업태와 항상 같다고 가정하지 않는다.

## 후보가 없거나 정보가 누락된 경우

- 연결된 실제 상품이 없으면 후보 없음으로 반환한다. 대표 메뉴 이름이나 `price_hint`만으로 후보를 보충하지 않는다.
- 일반 추천에서 카카오 신규 식당 검색·수집이나 CSV 파일 읽기를 실행하지 않는다.
- 가격 NULL은 허용하고 가격 확인 불가를 안내한다. 시간표가 없으면 영업시간 미확인을 안내한다.
- 확인된 예산 초과·휴무·폐업·영업시간 외는 제외한다. 품절·인분은 판정하지 않는다.
- 응답은 `menus`, `restaurants`, `warnings` 등 [API 설계서](API_DESIGN_v1.md)의 형식을 따른다. 업태 제외 건수 집계 필드는 제공하지 않는다.

## 저장 분류와 AI 요청

표시용 `catalog_food_type()`은 기존 `일식`을 `일식/회`, `샐러드`를 `기타`로 변환한다. 이는 식당 업태를 검사하는 `matches_food_type()`과 별개다.

Gemini의 조건 모델도 같은 `FoodType`을 사용한다. 질문 해석 지침은 `app/prompts/system_v4.txt`, 예시는 `examples_v3.json`, 고정 안내는 `replies_v4.json`이다. 분류를 변경하면 화면 선택지·요청 모델·프롬프트와 DB의 CHECK 제약을 함께 확인한다.

카카오 클라이언트에는 음식점·카페 그룹 검색 기능이 남아 있지만 일반 DB 추천 경로에서는 호출하지 않는다.

## 확인 방법

홈과 조건 변경 창의 15개 선택지를 확인한다. 중식은 `중식`·`중국식`, 치킨·술집은 `호프/통닭`을 허용하는지 확인한다. 추천 응답의 식당 ID로 DB의 업태·연결 상품을 대조하고, 후보가 없으면 상품 연결·가격·거리·영업 상태를 확인한다.

상세 규칙은 [DB 설계서](DB_DESIGN_v1.md), 수정 위치는 [코드 가이드](CURRENT_GUIDE_v1.md)를 참고한다.
