## 적용 원칙

화면 구성·탐색·버튼·카드·애니메이션은 원본 프론트를 기준으로 한다. 메뉴 후보·예산·위치·업종·영업시간·AI 사실 답변은 현재 백엔드를 기준으로 한다. 단순 폴더 덮어쓰기를 하지 않고 화면과 실행 연결을 분리해 적용한다.

일반 경로 `/`는 조건 입력 홈, `/ai`는 독립 챗봇, `/games/`는 게임, `/map/`은 식당 지도와 경로를 함께 보여준다. 원본의 게임 선택·실행 분리는 유지하되 `/games/#play`는 병합 단계에서 `/games/play`로 대응한다. 현재 게임 서버는 `/play` 정적 파일이 없으므로 허용 경로와 HTML 제공을 별도로 연결해야 한다. 해시가 필수인 기능은 발견되지 않았다.

## 비교에서 확인한 사실

1. `frontend/assets` 40개와 `games/dist/assets` 8개는 파일별 SHA-256이 모두 동일하다. 이미지·공통 헤더·위치/프로필 대화상자·화면 전환 자산을 새로 복제할 필요가 없다. 이미 있는 자산의 사용 연결을 비교한다.
2. `games/dist/engine.mjs`와 `minimal-ui.css`, `kakao-map/routes.js`와 `pin-overlaps.js`도 동일하다. 특히 engine 파일에는 큰 CSV 메뉴 배열이 있으므로 애니메이션 보조 함수 재사용과 CSV 후보 사용을 구분해야 한다.
3. 원본 프론트의 `frontend/app.js`는 `/api/menu-decisions`, `/api/restaurants/search`, `/api/routes`를 호출한다. 현재 백엔드 API와 다르므로 그대로 적용하면 연결되지 않는다.
4. 원본 게임의 후보와 AI 조건 해석은 `MENUS`, `filterMenus`, `parsePrompt`에 의존한다. 원본 Node 게임 서버도 로컬 메뉴를 후보로 만든다. 현재의 DB 후보 API·Groq 해석·공통 상태를 유지해야 한다.
5. 원본 홈의 예산 상한은 일부 코드에서 100,000,000원, 시간 입력 범위는 최대 180분이다. 게임 측은 일부에서 100~1,000m 반경을 사용하고 10분 미만 진입을 막는다. 현재 백엔드 계약은 예산 1,000~100,000원, 남은 시간 1~120분, 반경 50~500m다. 프론트의 모양을 유지하고 값 검증은 백엔드에 맞춘다.
6. 원본은 다인 요청에서 음식 종류를 전체로 바꾸는 코드가 있다. 현재 백엔드의 사용자가 선택한 음식 조건을 다인 게임에도 유지한다.
7. 원본 위치 자산은 `window.LunchRunLocation`을 선언하며 고정 장소 목록과 자체 저장소를 사용한다. 현재 같은 이름의 모듈은 Geolocation·카카오 주소 검색 어댑터다. 두 스크립트를 동시에 로드하면 충돌하므로 원본 대화상자의 외형만 적용하고 현재 위치 조회·검증을 연결한다.
8. 원본 홈의 식당·경로 화면은 예시 지도 이미지를 사용한다. 별도 `kakao-map` 화면에는 더 많은 대화상자와 지도 컨트롤이 있으나 정적 메뉴·주변 데이터 스크립트에 의존한다. 디자인 참고 대상으로 사용하고 데이터 실행은 현재 통합 지도 모듈을 유지한다.
9. 원본 게임의 가격·도보·총소요시간 일부는 추정 계산이다. 디자인을 가져오면서 DB 표시 가격·인분 미확인 안내와 실제 경로 응답으로 대체하고 미확인 소요시간은 사실처럼 표시하지 않는다.

## 파일별 처리

아래 경로는 각 프로젝트 루트 기준이다.

| 파일/영역 | 처리 | 수정 이유 |
|---|---|---|
| `frontend/index.html`, `styles.css` | 프론트 디자인 적용 | 공통 헤더·레이아웃·버튼·조건 입력·AI 화면 외형. 현재 base URL과 공통 스크립트 연결 유지 |
| `frontend/app.js` | 필요한 렌더링만 이식 | 일반 URL·DB 요청 형식·조건 무효화·공통 상태는 현재 코드 유지 |
| `frontend/api.js`, `state.js` | 현재 코드 유지 | 실제 API 계약과 위치·조건·메뉴·식당 상태 공유 |
| `frontend/chat.js`, `chat.css` | 동작 유지, 디자인 연결 | `/ai`의 프론트 말풍선·입력창에 스트리밍·세션·조건 변경안·Enter 기능 연결 |
| `frontend/location.js`, `location-picker.js`, `location-picker.css` | 현재 동작 유지, 외형 적용 | 실제 현재 위치·주소/장소 검색 유지, 고정 역 목록으로 되돌리지 않음 |
| `frontend/assets/*`, `games/dist/assets/*` | 동일 자산 재사용 | 전체 48개 동일. 필요한 script/style 연결만 적용 |
| `games/dist/index.html`, 각 CSS | 프론트 디자인 적용 | 선택/실행 화면 분리와 원본 레이아웃·버튼·애니메이션 유지 |
| `games/dist/app.mjs` | 렌더링과 URL 연결 선별 적용 | 후보는 DB, AI는 `/ai`, 식당과 경로는 `/map/` 사용 |
| `games/dist/backend.mjs` | 현재 코드 유지 | DB 후보 조회와 실제 가격·상태 전달 |
| `games/dist/rooms.mjs`, `rooms.css` | 프론트 방 화면 + 현재 통신 유지 | 다인 게임 화면을 유지하면서 DB 메뉴 ID·후보·조건을 사용 |
| `games/dist/engine.mjs` | 그대로 유지 | 동일 파일. DB 후보를 인수로 주는 추첨 보조 함수 사용, CSV를 추천 근거로 사용하지 않음 |
| `games/server.mjs`, `games/app.py` | 현재 로직 유지, 필요 시 URL/자산 제공만 보완 | DB 후보 방 API·프록시를 유지하고 `/games/play` 직접 접속 지원 |
| `kakao-map/index.html`, `styles.css` | 프론트 버튼·카드·대화상자 외형 적용 | 기존 지도+경로 통합 구조에 프론트 디자인을 입힘 |
| `kakao-map/integration.js` | 현재 기능 유지, DOM 연결 보완 | DB 식당·상세·현재 위치·지도·경로·클러스터 동작 유지 |
| `kakao-map/routes.js`, `pin-overlaps.js` | 그대로 유지 | 동일 파일이며 숫자 클러스터와 경로 보조 기능 사용 |
| `kakao-map/app.js`, `data.js`, `menus.js`, `nearby-*.js` 등 원본 데이터 모듈 | 실행 연결을 가져오지 않음 | CSV·예시 데이터가 현재 DB 결과를 덮는 것을 방지 |
| `app/main.py`, `app/map_routes.py` | 데이터 로직 유지, 필요 시 화면 제공 부분만 연결 | 일반 URL 새로고침·정적 자산·기존 API 경계 유지 |
| `app/services.py`, `db_recommendations.py`, DB 모델·마이그레이션·프롬프트 | 현재 코드 유지 | 이번 병합에서 DB 중심 추천·AI 정책을 변경하지 않음 |
| `.env`, DB 데이터, 적재·수집 스크립트 | 유지 | 병합을 위한 재적재·스키마 변경 없음 |
| `frontend/bundle.js` | 마지막에 재생성 | 원본 번들을 덮어쓰지 않고 연결한 소스로 빌드 |

프로필 UI는 원본이 닉네임을 로컬에 저장하는 게스트 기능이다. 필요한 헤더·대화상자 디자인을 연결해도 실제 로그인이나 Supabase Auth를 새로 구현하지 않는다.

## 화면 대응

|---|---|
| `/#conditions` | `/` |

`/games/play`는 계획 경로이며 이번 비교 단계에서 추가하지 않았다. 이 경로를 실제로 연결할 때 게임 HTML의 상대 자산 경로와 직접 접속·새로고침·뒤로가기를 함께 검증한다.

## 다음 단계와 검증

2단계는 홈·공통 헤더·조건 입력 디자인을 적용하고 현재 위치·조건·일반 경로·상태 공유를 연결한다. 이어 게임 선택/실행 디자인과 DB 후보를 연결하고, 독립 AI 디자인을 연결한 다음 통합 `/map/`을 프론트 디자인으로 맞춘다.

각 단계마다 변경 파일과 내용을 먼저 보고하고 진행 승인을 받는다. 검증은 직접 접속·새로고침·역순 이동, 위치/조건 변경 시 이전 결과 무효화, 게임 애니메이션, AI 대화와 Enter/Shift+Enter, 지도·클러스터·길찾기, API 후보 일치와 DB 무수정 여부를 포함한다. 화면 비교는 같은 화면 크기에서 원본과 병합본을 캡처하여 확인한다.
