- 원본 `C:\temp\aio-04-p1-team4\frontend`의 홈 HTML과 CSS를 적용했다. 로고·고정 공통 헤더·위치 버튼·게스트 표시·조건 카드·색상·하단/우측 내비게이션 외형을 사용한다.
- 기존의 시안 검토 툴바를 사용자 화면에서 제거했다. 시안 이미지와 gallery 파일은 삭제하지 않았다.
- 공통 프로필 자산의 닉네임 대화상자를 연결했다. 브라우저 내 게스트 닉네임 기능이며 실제 로그인·회원가입·Supabase Auth는 추가하지 않았다.
- 내비게이션은 원본과 같은 조건 설정·AI 추천·게임 선택·식당 선택·경로 확인의 5개 항목으로 구성했다. 일반 경로와 현재 백엔드 연결을 유지한다.
- CSS 원본은 `frontend/styles.css`에 적용하고, 백엔드 연결에 필요한 배치 보완은 `frontend/home-integration.css`에 분리했다.

## 유지한 기능

원본의 `assets/location-dialog.js`는 로드하지 않는다. 동일한 전역 이름을 사용하는 현재 위치 어댑터와 충돌하거나 고정 역 목록으로 되돌아가지 않도록 기존 `location.js`·`location-picker.js`를 유지했다. Geolocation, 주소·장소 검색, 주소 변환 실패 시 좌표 유지, 늦은 응답 차단도 유지했다. 위치 대화상자의 색상·테두리·버튼 외형만 공통 디자인에 맞췄다.

홈은 기존 15개 음식 조건과 DB 후보·가격 범위·식당 수·인분 미확인 표시를 유지한다. 다인 이용에서도 음식 조건을 선택할 수 있다. 원본의 카테고리 비활성화나 전체 음식으로의 강제 변경은 적용하지 않았다.

입력 검증은 기존 예산 1,000~100,000원, 반경 50~500m와 남은 시간 1~120분 기준을 유지했다. 일반 경로 `/`, `/ai`, `/budget`, `/time`, `/distance`, `/people`, 공통 상태·DB 요청 형식과 조건 변경 시 결과 무효화를 유지했다. 서버·DB 모델·추천 판정·Groq 대화 로직·게임 애니메이션·지도 로직은 이번 단계에서 수정하지 않았다.

## 화면 배치 보완

원본은 홈에 음식 분류 6개를 보여주지만 현재 백엔드는 15개다. 같은 크기의 한 줄 디자인을 그대로 적용하면 우측 메뉴와 겹치므로 데스크톱은 4열로 배치하고 카드·간격을 조정했다. 화면 우측 내비게이션과 조건 영역이 겹치지 않고 실행 버튼이 푸터 위에 오도록 검증했다.

모바일에서는 원본의 고정 캔버스를 축소하면 글자가 지나치게 작아지고 제목이 헤더에 가려졌다. 같은 카드·색상·버튼 디자인을 유지하면서 화면 너비에 맞는 2열 입력·음식 분류와 세로 스크롤을 적용했다. 고정 하단 내비게이션 아래에도 내용을 확인할 수 있도록 여백을 확보했다.

공통 스타일을 적용한 후 기존 AI의 게임/지도 이동 링크가 푸터와 겹친 문제는 AI 패널의 스크롤 범위를 제한해 해결했다. AI의 상세 디자인 병합은 이후 단계에서 진행한다.

## 검증

- 정적 화면·홈 시각 점검·DB 브라우저 흐름·실제 위치 선택 흐름·AI 대화 회귀 검사를 확인했다. 해당 범위의 Python 테스트는 7개다. 공통 스타일 영향으로 처음 실패한 AI 링크 접근도 수정 후 통과했다.
