## 적용 내용

- 원본 게임의 HTML과 기본·화이트 테마·데이터 배치·다인 방 CSS를 적용했다. 공통 헤더, 게임 선택 카드 이미지, 가챠 그림, 실행·결과 화면, 우측/하단 내비게이션을 원본에 맞췄다.
- 메뉴 후보·추첨·입력 검증·다인 방 통신은 현재 백엔드 연결 코드를 유지했다. 원본 게임 서버의 CSV 후보 생성이나 클라이언트의 추정 가격·소요시간 판정은 가져오지 않았다.
- 혼자 게임 4종(제비뽑기·가챠·행운권·랜덤 게임), 함께 게임의 룰렛·사다리와 기존 백엔드의 ‘우리의 교집합’을 유지했다. 교집합 선택 카드도 같은 카드 디자인으로 제공한다.
- 원본 이미지는 기존 자산을 재사용했다. `engine.mjs`는 수정하지 않았고 추첨 보조 함수에 DB 후보를 전달한다. 이 파일에 남아 있는 이전 메뉴 배열은 추천 근거로 사용하지 않는다.

## 일반 경로

| 화면 | 주소 |
|---|---|
| 조건 입력 홈 | `/` |
| AI 챗봇 | `/ai` |
| 게임 선택 | `/games/` |
| 게임 실행·결과 | `/games/play` |
| 식당 지도·경로 | `/map/` |

게임 카드를 선택하면 `/games/play`로 이동한다. 브라우저 뒤로 가기로 선택 화면에 돌아가고 앞으로 가기로 결과를 복원한다. 새로고침과 직접 접속도 지원한다. 이전 `#games`·`#play` 북마크는 일반 URL로 정리한다. 본문 바로가기의 `#main`은 페이지 내부 접근성 앵커이며 화면 라우터가 아니다.

Node 서버는 허용한 실행 경로에 게임 HTML을 제공하며 알 수 없는 파일은 404로 유지한다. FastAPI의 기존 게임 프록시는 그대로 사용한다. Node 직접 접속에서도 새 경로와 공통 헤더 자산이 깨지지 않도록 호환했다. 전체 앱은 기존처럼 `http://127.0.0.1:8000`으로 접속한다.

이전 내부 탭이 저장되어 있어도 일반 게임 주소에서는 선택·실행 경로를 우선한다. 조건·메뉴·결과 데이터와 즐겨찾기 데이터는 기존 저장 방식을 유지한다.

## 유지한 백엔드 기준

게임은 `/api/menus/candidates`에서 받은 DB 메뉴만 사용한다. 위치·예산·반경·업종·영업시간 판정, 조건 변경 시 이전 결과 무효화, 후보 없음 안내는 기존 기능을 유지한다. 입력값을 추첨하는 다인 게임도 현재 후보 메뉴와 일치해야 식당 조회로 연결된다.

표시 가격·가격 범위·식당 수·인분 미확인·판매 상태 미확인 정보를 결과에 표시한다. 1인분 가격이나 총 이동·대기·식사시간을 추정해 확정 정보로 안내하지 않는다. 원본에 있던 ‘모든 시간 조건 만족’ 문장도 가져오지 않았다.

AI 버튼은 독립 `/ai`로 연결하고 식당 찾기와 경로 버튼은 통합 `/map/`을 사용한다. AI·지도 자체의 디자인은 이번 단계에서 변경하지 않았다. 실제 위치 조회·주소/장소 검색과 게스트 닉네임 기능도 현재 연결을 유지한다.

## 다인 방 보완

- 초대 링크로 처음 들어온 참여자는 `/games/play?room=...`에서 바로 닉네임을 입력해 참여한다.
- 참여·복원 시 방의 위치·업종·예산·메뉴 후보를 공통 상태에 반영한다. 최초 입장에서도 방 조건을 즉시 적용하도록 보완했다.
- 최종 메뉴 선택 후 방 문맥을 닫고 지도에 이동할 때 초대 쿼리를 정리한다. 지도에서 뒤로 돌아와도 방 재진입 때문에 선택 메뉴가 초기화되지 않는다.
- 초대 진입 전에는 개인 위치 기준 메뉴 조회를 건너뛴다. 방 조건을 받을 참여자에게 잘못된 위치 미설정 경고가 표시되지 않도록 했다.
- 원본 다인 방 스타일을 연결하고, 메뉴 선택 카드에서도 인분 미확인 표시를 유지했다. 실제 QR 이미지 생성도 확인했다.
