# 프론트 병합 4단계: 독립 AI 화면

작업일: 2026-11-13. 작업 대상: `C:\temp_resolved`. 디자인 참고: `C:\temp\aio-04-p1-team4\frontend`.

## 적용 내용

- 독립 `/ai` 화면에 원본의 흰 대화 영역, 회색 AI 말풍선, 주황색 사용자 말풍선, 둥근 입력창과 전송 버튼 디자인을 적용했다.
- 공통 헤더·닉네임 표시·우측 하단 사이드바를 유지했다. 모바일에서는 하단 내비게이션과 세로 스크롤을 유지한다.
- 원본의 대화 모양은 사용하되 예시 답변이나 데모 메뉴 선정은 가져오지 않았다. 기존 DB 챗봇의 답변과 확정 조건만 표시한다.
- 사용자 말풍선에는 로컬 닉네임이 있으면 표시하고, 이름과 답변은 기존처럼 HTML 이스케이프 처리한다. 닉네임을 새 API 항목으로 전송하지 않는다.
- 입력창은 기존 500자 제한, Enter 전송, Shift+Enter 줄바꿈과 한글 조합 중 전송 방지를 유지한다.
- 기존 조건 변경안·적용 버튼, 진행 상태·스피너, 취소·오류·재시도, 선택 메뉴·인분 미확인 표시도 같은 디자인으로 연결했다.

## 유지한 실행 흐름

Groq 의도 해석, Lunchrun DB 메뉴·식당 조회, 식당 가격·영업 질문, 변경안 확인 후 적용, NDJSON 진행 상태와 최종 응답 처리, 대화 복원과 오래된 응답 차단은 기존 코드를 유지했다. 서버·프롬프트·DB 구조·추천 판정은 수정하지 않았다.

화면 위의 조건 요약과 출발 위치를 표시한다. 남은 시간은 기존 종료 시각 기준 기능을 유지하며, 별도 고정 숫자를 대화에 추가하지 않는다. 조건 변경을 적용하면 기존 메뉴와 식당 결과가 무효화된다. 새로고침으로 서버 대화를 복원할 때도 현재 화면 조건을 과거 조건으로 덮어쓰지 않는다.

홈과 게임의 AI 버튼은 `/ai`로 연결된다. 식당 조회 후 기존 ‘게임으로 이동해 지도 보기’ 연결을 유지하며 공통 상태의 선택 메뉴·조건·식당 결과가 게임과 지도에 전달된다. 지도와 경로는 기존 `/map/`에서 처리한다.

## 배치 보완

대화는 원본과 같은 고정 높이 영역 안에서 스크롤한다. 조건 변경 카드·입력창·선택 메뉴 등 나머지 내용은 페이지 흐름에 배치했다. 전체 AI 패널을 한 번 더 고정 높이로 자르던 임시 스타일을 제거하여 입력창이나 이동 링크가 푸터 뒤에 가려지지 않도록 했다.

데스크톱은 오른쪽 사이드바와 겹치지 않는 폭을 사용하고 전송 버튼은 원본의 큰 주황색 버튼 비율을 적용했다. 모바일에서는 말풍선과 입력 글자 크기를 조정하고 전송·취소·재시도 버튼을 화면 너비에 맞췄다.

- 관련 Python 테스트는 중복 실행을 제외한 **7개**가 통과했다. AI 디자인, 홈 디자인, 대화 브라우저 흐름, DB 게임·지도 흐름과 일반 페이지 경계를 포함한다.
- 전체 Node 화면·상태·위치·채팅·게임 검사 **35개**가 통과했다.
- 데스크톱 1516×1038과 모바일 390×844에서 원본 AI 화면과 병합 화면을 캡처해 비교했다.
- 실제 DB 기반 메뉴 추천 → 식당 조회 → 식당 가격 질문, 인분 미확인 표시, 변경안 적용 전후 상태, 재추천, 새로고침 후 대화·조건 보존을 확인했다.
- 오류 응답 뒤 재시도, 진행 중 스피너와 취소, Enter/Shift+Enter, HTML 이스케이프·이전 응답 차단을 확인했다. 데스크톱 입력 폼과 푸터·사이드바 겹침, 모바일 가로 넘침도 검사했다.
- JavaScript 문법 검사와 이번 변경 파일의 공백 검사를 완료했다. Starlette TestClient의 기존 의존성 경고는 유지된다.
