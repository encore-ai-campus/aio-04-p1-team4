# 일반 URL 경로 전환

> 후속 게임 병합에서 `/games/play`를 실행·결과 경로로 추가했다. 현재 게임 선택/실행 구성은 [3단계 게임 병합 결과](frontend_merge_stage3_results.md)를 참고한다. 아래 게임 설명은 일반 URL 전환 당시의 기록이다.

작업일: 2026-11-13. 대상: `C:\temp_resolved`.

## 적용 주소

| 화면 | 주소 |
|---|---|
| 홈·조건 입력 | `/` |
| AI 채팅 | `/ai` |
| 예산 설정 | `/budget` |
| 시간 설정 | `/time` |
| 거리 설정 | `/distance` |
| 인원 설정 | `/people` |
| 게임 | `/games/` |
| 지도·식당·경로 | `/map/` |

기존 홈 시안 검토 화면인 참가자 입력·추첨·결과도 `/group-input`, `/play`, `/result`로 제공한다. 실제 메뉴 게임은 기존 `/games/`를 유지한다. 게임 안의 선택·실행 상태는 기존 코드로 처리하며 새 게임 단계나 애니메이션은 추가·변경하지 않았다.

홈의 화면 판정은 `location.pathname`, 페이지 내부 전환은 `history.pushState`, 뒤로가기는 `popstate`를 사용한다. FastAPI에 허용한 화면 경로만 등록하여 직접 접속·새로고침 시 동일한 HTML 셸을 제공한다. 알 수 없는 URL과 API는 기존처럼 404를 유지한다. HTML의 base URL을 `/`로 고정하여 화면별 주소에서도 스타일·이미지·스크립트가 정상 로딩된다.

게임 AI 버튼도 `/ai`로 이동한다. 기존 게임 저장 상태가 AI 모드였다면 게임 화면으로 복귀할 때 일반 게임 모드로 복원한다. 실제 챗봇은 같은 대화·스트리밍·조건 변경·DB 조회 기능을 사용한다.

## 이전 주소

`/conditions`는 `/`로, `/restaurants`와 `/route`는 `/map/`으로 연결한다. 이전 `/#conditions`, `/#ai` 등 홈 화면 해시는 일반 주소로 정리하며, `/#games`는 `/games/`, `/#restaurants`와 `/#route`는 `/map/`으로 연결한다. 이 처리는 이전 북마크 호환을 위한 변환이며 정상 화면 전환에 해시를 사용하지 않는다. 해시 경로가 필수인 기능은 발견되지 않았다.

## 유지 범위

DB 모델·추천 조건·Groq 해석·카카오 지도·길찾기 API는 변경하지 않았다. 기존 화면 디자인과 게임 애니메이션을 유지했다. `C:\temp` 프론트의 디자인 병합은 아직 진행하지 않았으며 `C:\TeamProject_1`도 수정하지 않았다.

## 검증

일반 경로 전환 후 정적 화면·브라우저 회귀 검사 7개가 통과했다. 직접 접속, AI 새로고침과 대화 복원, 홈 복귀 시 조건 보존, 게임→지도 및 역순 이동, 게임 AI 버튼의 독립 화면 이동, 위치 선택과 게임 애니메이션을 확인했다. Node 화면·상태·게임 테스트는 35개가 통과했다. 외부 응답은 기존 테스트 대역을 사용하며 프로젝트 실제 DB를 변경하지 않는다.
