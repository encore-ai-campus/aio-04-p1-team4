# LunchRun 메뉴 카탈로그 설계 v1

- 작성일: 2026-11-10
- 적용 단계: 챗봇 개편 2단계
- 적용 코드: `app/database/models.py`, `app/database/seed.py`, `app/menu_catalog.py`

## 목적

기존 `menu` 테이블은 특정 식당 상세페이지에서 확인한 실제 메뉴와 가격을 저장한다. 랜덤 추천에 사용할 대표 메뉴까지 같은 테이블에 넣으면 실제 매장 데이터와 추천 기준 데이터가 섞인다.

따라서 같은 SQLite DB 안에 `menu_catalog`와 `menu_alias`를 추가했다. 별도 DB 서버는 사용하지 않는다.

## 테이블 책임

### menu_catalog

- `id`: 이후 채팅 상태에서도 사용할 안정적인 메뉴 ID
- `name`: 화면에 표시하는 대표 메뉴명
- `normalized_name`: 공백과 문장부호를 제거한 비교 이름
- `cuisine`: 한식·중식·일식·양식·샐러드 분류
- `search_keyword`: 카카오 장소 검색에 사용할 검색어
- `description`: 메뉴 설명
- `price_hint`: 실제 데이터가 없을 때 예산 후보를 좁히는 카탈로그 기준값
- `active`: 추첨 대상 사용 여부

`price_hint`는 실제 매장 가격이 아니다. 화면에 확인 가격으로 표시하지 않는다.

### menu_alias

돈가스와 돈까스처럼 같은 대표 메뉴를 가리키는 이름을 저장한다. `normalized_name`은 전체 테이블에서 고유하므로 하나의 별칭이 여러 대표 메뉴에 연결되는 모호함을 막는다.

### menu

기존 역할을 유지한다. 식당 ID, 상세페이지의 실제 메뉴명, 실제 확인 가격과 가격 상태를 저장한다. 이번 단계에서는 카탈로그 FK를 추가하지 않았다.

## 후보 선정 순서

1. 활성 카탈로그에서 음식 종류와 제외 메뉴를 적용한다.
2. 사용자 위치 반경 안의 식당만 확인한다.
3. 상세 메뉴 수집 상태가 `success`인 식당만 실제 근거로 사용한다.
4. 가격 상태가 `known`이고 예산 이내인 실제 메뉴를 찾는다.
5. 실제 메뉴명을 대표 이름과 별칭에 연결한다.
6. 실제 근거가 하나라도 있으면 해당 후보만 반환한다.
7. 실제 근거가 없으면 `price_hint`가 예산 이내인 카탈로그 후보를 반환한다.

결과의 `source`가 `database`이면 주변 실제 메뉴·가격 근거가 있다는 뜻이다. `catalog`이면 주변 판매와 실제 가격은 아직 확인 전이다.

## 재추천

`excluded_menu_ids`에 직전 메뉴 ID를 전달하면 해당 메뉴를 후보에서 제외한다. 모든 후보가 제외되면 `None`을 반환하며, 상위 채팅 로직이 조건 변경을 안내한다.

## 초기 데이터

기존 데모 메뉴 ID 10개를 초기 카탈로그 ID로 유지했다. 서버가 여러 번 시작돼도 누락된 메뉴와 별칭만 추가하며 기존 DB 값을 덮어쓰지 않는다.

## PostgreSQL 전환

ORM 모델과 조회 서비스는 SQLAlchemy를 사용하므로 PostgreSQL에서도 재사용할 수 있다. 데이터가 커지면 현재 Python 하버사인 거리 계산을 PostgreSQL 위치 인덱스 또는 PostGIS 조회로 교체한다.
