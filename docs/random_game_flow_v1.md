# 랜덤 게임 메뉴 추첨·식당 검색 분리 v1

- 작성일: 2026-11-11
- 적용: 기존 게임 흐름을 이 문서의 2단계 방식으로 변경한다.

## 사용자 흐름

1. 위치와 음식 조건을 설정한다.
2. `랜덤 메뉴 뽑기`를 누르면 현재 조건에 맞는 메뉴만 표시한다.
3. 마음에 들지 않으면 `한번 더!`로 다시 추첨한다.
4. `이 메뉴로 식당 찾기`를 누르면 지도 화면으로 이동한다.
5. 선정 메뉴 ID와 동일한 위치·반경·음식 조건으로 식당을 검색한다.
6. 필요한 상세정보를 수집하고 가격·영업시간을 판정한 결과를 지도에 표시한다.

## 조건 적용

- 메뉴 추첨에는 음식 종류와 예산을 적용한다.
- 위치·반경은 저장된 주변 메뉴 근거를 찾는 데 사용한다.
- 실제 확인된 주변 메뉴가 있으면 해당 근거를 우선 사용한다.
- 실제 근거가 부족하면 카탈로그 기준가격으로 후보를 좁힌다. 이 기준가격은 실제 식당 가격을 보장하지 않는다.
- 채식·맵기·총소요시간은 현재 데이터로 검증하지 않는다.
- 조건에 맞는 메뉴가 없으면 조건 변경 안내를 표시하고 외부 검색을 시작하지 않는다.

## 구현

- `POST /api/menus/draw`: 기존 `services.recommend()`를 `search_restaurants=False`로 호출한다. 카카오 검색·Playwright·Groq 호출은 없다.
- `drawMenu()`: 메뉴 전용 API를 호출한다.
- `findSelectedRestaurants()`: 메뉴 ID와 현재 조건을 고정한 뒤 지도 이동과 `/api/recommendations` 요청을 실행한다.
- 검색 중에는 지도에 검색 안내를 표시하고, 실패하더라도 뽑힌 메뉴를 보존한다.
- 기존 채팅과 식당 추천 API 동작은 유지한다.

## 직접 검증

1. 서버를 재시작하고 브라우저를 새로고침한다.
2. 음식 종류 `중식`, 예산 `9,000원`을 설정한다.
3. 게임에서 메뉴를 뽑는다. 기본 카탈로그만 있다면 짜장면이 선택된다. 실제 주변 가격 근거가 있으면 예산 내 다른 중식 메뉴도 가능하다.
4. 개발자 도구 Network에서 `/api/menus/draw`만 호출되고 `/api/recommendations`는 호출되지 않는지 확인한다.
5. `이 메뉴로 식당 찾기`를 누르면 지도로 이동하고 `/api/recommendations`에 선정된 `menu_id`가 전달되는지 확인한다.

## 별도 확인 사항

이 수정은 메뉴 추첨 단계에서 상세수집을 제거한다. 지도 단계의 Playwright는 기존 실행 환경을 사용하므로 앞서 확인한 Windows 이벤트 루프 오류는 별도로 해결해야 한다. 실제 외부 검색·브라우저 실행은 자동 테스트에서 모의 처리했다.
