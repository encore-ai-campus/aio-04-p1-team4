# LunchRun-demo 6단계 통합 검증

검사일: 2026-11-08. 공개 기준 장소: 가산디지털단지역 7호선.
검증 대상: 로컬 FastAPI, Groq, 카카오 검색·지도. 배포는 수행하지 않았습니다.

## 결과

| 검증 | 결과와 방법 |
|---|---|
| 자동 검사 | 백엔드 38개 통과, 실제 호출용 1개 기본 생략. 프론트 24개 통과 |
| 장소 검색 | 실제 카카오 장소 검색 → 선택 → 조건 완료 → 추천 화면 이동 통과 |
| 챗봇 조건 변경 | 실제 Groq으로 예산 9000원·반경 200m 제안, 적용 전 값 유지·적용 후 요약 갱신 통과 |
| 실제 식당 검색 | 짜장면 검색으로 반경 200m 안 후보 7곳 반환, 화면에는 4개 표시 |
| 지도 이동 | Yes 버튼으로 지도 이동, 기준 위치·식당 마커·점선 원 확인 |
| 목록 페이지 | 첫 페이지 5개, 다음 페이지 2개와 해당 마커 일치 |
| 마커 선택 | 마커 클릭 후 카드·마커의 식당명 일치 |
| 추첨 | 실제 5초 추첨 후 카드·마커 식당명 일치, 한번 더 버튼 표시 |
| 모바일 | viewport 390×844 설정, 지도 높이 380px·카드 높이 125px, 페이지 가로 넘침 없음. 실제 기기 검사는 아님 |
| 반경 경계 | 모바일 조건 창의 49m 유효성 검사 거부, 50m 적용 후 카드·식당 마커 제거 |
| 빈 결과 | 50m 짜장면 검색 후보 없음 안내, 카드 0개, 자동 반경 확대 없음 |
| 실제 가드레일 | 1km 요청에 50~500m 안내, 확정 반경 50m 유지 |
| 오류·권한 거부 | 모의 통신/브라우저 API 검사로 Groq·카카오 인증·권한·사용량·시간 초과·형식 오류, 위치 권한 거부·지연 검증 |

실제 브라우저 검증은 수정 전 자동 검사 후 수행했고, 아래 결함 수정 뒤 관련 프론트 자동 검사를 다시 실행했습니다.
오류를 실제 계정에서 강제로 발생시키거나 브라우저 위치 권한을 바꾸지는 않았습니다.
위치 재설정의 주소 검색 모드, 실제 GPS 기기 정확도, 여러 실기기·브라우저 동작은 이번에 별도 실측하지 않았습니다.
메뉴 설명·알레르기·키 공개 표본은 이전 단계 검사 기록을 참고하며 이번 브라우저 세션에서 모두 재실행하지 않았습니다.

## 발견·수정한 결함

추첨 중 새 검색을 시작하는 코드 경로에서 이전 타이머가 남을 수 있었습니다.
새 메뉴 검색은 이전 결과·제안·추첨을 무효화하고, 새 채팅은 진행 중 추첨을 중단합니다.
재검색 시 오래된 제안 차단과 채팅 실패 후 추첨 비활성 유지 검사를 추가했고 모두 통과했습니다.

## 직접 다시 확인하기

1. 프로젝트 폴더에서 기존 서버를 Ctrl+C로 종료하고 아래 명령으로 실행합니다.
2. http://127.0.0.1:8000 접속, Ctrl+F5로 새로고침합니다.
3. 공개 장소를 검색하고 조건 완료를 누릅니다.
4. `예산 9000원, 반경 200m로 바꿔줘` → 변경안 확인 → 적용.
5. `짜장면 파는 식당 보여줘` → 카드 확인 → Yes 지도 이동.
6. 카드·마커·다음 페이지·추첨을 확인합니다.
7. 조건 수정에서 반경 50m 적용 후 다시 검색하고 빈 결과 또는 새 결과를 확인합니다.

실제 결과 수는 외부 데이터 변경에 따라 달라집니다.

PowerShell 실행:

`.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`

백엔드 검사: `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`

프론트 검사: `node --test tests/location.test.cjs tests/location-flow.test.cjs tests/restaurant-ui.test.cjs tests/map.test.cjs`

## 설정과 자주 발생하는 오류

- 필수: MAP_API_KEY(카카오 REST 키). 지도에는 KAKAO_JAVASCRIPT_KEY, 채팅에는 GROQ_API_KEY가 필요합니다.
- Groq 모델·출력 한도·30초 제한은 CHAT_POLICY_GUIDE.md를 참고하세요. 설정 변경 후 서버를 재시작합니다.
- 지도 SDK의 도메인 불일치: 실제 접속 주소를 카카오 웹 도메인 설정과 맞춥니다. localhost와 127.0.0.1은 서로 다릅니다.
- AI 구버전 응답: 브라우저 새로고침만으로 Python 서버 코드는 갱신되지 않습니다. 서버도 재시작합니다.
- 429/사용량 오류: 잠시 후 재시도합니다. 자동 반복 호출이나 반경 자동 확대는 하지 않습니다.
- 출력 잘림: GROQ_MAX_COMPLETION_TOKENS를 점검합니다. 추론 토큰도 한도에 포함됩니다.
- Python 실행 파일 접근 오류: 설치된 Python과 가상환경 경로를 확인하세요. 이번 검사는 실행 권한이 허용된 환경에서 수행했습니다.

## 배포 준비 상태와 남은 범위

로컬 데모 핵심 흐름은 검증했습니다. 특정 무료 호스팅의 설치·실행은 검증하지 않았습니다.
Groq 모델 파일은 서버에 저장하지 않습니다. 다만 requirements.txt에는 현재 데모에서 사용하지 않는
transformers·streamlit 등도 포함되어 있으므로 실제 배포 전 의존성 정리가 필요합니다(이번에는 변경하지 않음).

배포 전에는 서비스에 맞는 host/port 실행 명령, HTTPS, 외부 HTTPS 요청 허용, 서버 비밀 환경변수,
배포 URL의 카카오 도메인 등록, 요청 제한·절전 정책을 확인해야 합니다.
공개 서비스 운영에는 사용자별 호출 제한·실제 회원 인증·개인정보 처리 정책 등 별도 설계가 남아 있습니다.
실제 매장 메뉴 가격·채식·맵기·조리/대기/이동시간은 계속 미검증이며 Supabase Auth·DB·Redis는 미연결입니다.
