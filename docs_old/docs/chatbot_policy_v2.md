# LunchRun 챗봇 추천 정책 v2

- 작성일: 2026-11-10
- 상태: 4단계 Groq 가드레일 적용 버전
- 이전 버전: `chatbot_policy_v1.md`
- 코드에는 이 버전의 의도 체계와 안전 규칙을 적용한다.

## 1. 역할 분리

- Groq는 사용자 문장을 **구조화된 의도와 조건 변경안**으로 해석한다.
- FastAPI 서버는 해석 결과를 Pydantic으로 검증하고 실제 동작 여부를 결정한다.
- 메뉴 추첨, 식당 검색, 가격·영업시간 판정은 서버와 DB가 담당한다.
- Groq가 식당명, 가격, 주소 또는 영업 여부를 만들어 답하지 않는다.

## 2. 지원 의도

| 의도 | 의미 | 현재 동작 |
|---|---|---|
| `recommend_menu` | 현재 조건으로 메뉴 선정 | 메뉴 카탈로그 후보에서 선정 |
| `reroll_menu` | 다른 메뉴 재선정 | 현재 메뉴를 제외하고 선정 |
| `search_restaurants` | 선정 메뉴의 식당 검색 | 기존 추천 서비스 실행 |
| `ask_menu_detail` | 메뉴 관련 후속 질문 | 서버가 보유한 메뉴 정보로 안내 |
| `ask_restaurant_detail` | 식당 가격·주소·영업 후속 질문 | 대상만 판별하며 실제 DB 답변은 5단계에서 연결 |
| `change_conditions` | 반경·예산·음식 종류 변경 | 변경안을 반환하며 서버가 범위를 검증 |
| `clarify` | 값이나 대상이 부족함 | 확인 질문과 `pending_action` 저장 |
| `out_of_scope` | 추천 범위 밖 질문 | 정해진 범위 안내 후 추천 상태 유지 |

기존 `explain_menu`는 이전 테스트와 호출의 호환을 위해 임시로 허용하지만, 새 프롬프트는 `ask_menu_detail`을 사용한다.

## 3. Groq에 전달하는 문맥

최근 대화는 최대 10턴을 전달한다. 메시지와 별도로 다음 상태를 전달한다.

- 현재 선택 메뉴 ID와 이름
- 최근 추천 식당의 ID와 이름
- 확인 필요 후보 식당의 ID와 이름
- 현재 음식·예산 조건과 검색 반경
- 현재 확인 대기 항목
- 유효한 메뉴 카탈로그 ID와 이름

정확한 위치 좌표와 식당의 실제 가격, 주소, 영업 여부는 Groq에 보내거나 판단용 사실로 맡기지 않는다. 식당 대상은 현재 세션에 있는 ID만 선택할 수 있다.

## 4. 안전 검증

1. Groq 응답은 JSON으로 받아 Pydantic 스키마로 검증한다.
2. 메뉴 ID는 현재 메뉴 카탈로그에 있는 값만 허용한다.
3. 식당 ID는 현재 추천 또는 후보 목록에 있는 값만 허용한다.
4. 의도와 필수 필드가 맞지 않으면 실행하지 않는다.
5. JSON 형식 또는 스키마 오류일 때만 한 번 다시 해석을 요청한다.
6. 두 번째 응답도 잘못되면 외부 원문을 노출하지 않고 안전한 `clarify`로 전환한다.
7. 인증, 사용량 제한, 서버 오류, 시간 초과와 네트워크 오류는 무작정 재시도하지 않고 정제된 오류로 반환한다.

## 5. 조건 변경과 확인 대기

- 값이 명확한 변경은 `condition_patch`로 반환한다.
- 값이 없는 반경·예산 변경은 `clarify`로 분류하고 세션에 `pending_action`을 기록한다.
- 정상 추천 요청이 성공하면 이전 확인 대기를 해제한다.
- 위치 변경은 임의의 좌표로 추측하지 않는다.

## 6. 추천과 재추천

- 메뉴 재추천 시 현재 선택 메뉴를 후보에서 제외한다.
- 다른 후보가 없으면 같은 메뉴를 반복 확정하지 않고 조건 변경이 필요함을 안내한다.
- 식당 추천은 여전히 서버가 카카오 검색과 저장된 DB 정보를 이용해 수행한다.

## 7. 지원 범위 밖 질문

추천과 관계없는 질문에는 다음 문장을 사용한다.

> 메뉴 및 식당 선정에 맞는 대화를 입력해주세요.

이 응답은 현재 조건, 선택 메뉴와 최근 추천 식당을 변경하지 않는다.

## 8. 현재 구현 경계

4단계는 Groq의 문장 해석과 문맥 전달을 교체한 단계다. `ask_restaurant_detail`에서 특정 식당을 식별할 수는 있지만, 해당 식당의 메뉴·가격·주소·영업시간을 DB에서 조회해 자연어 답변으로 만드는 기능은 5단계에서 연결한다. 따라서 현재는 확인 가능한 대상임을 알리는 안전한 안내를 반환한다.

메뉴 선정의 실행 부분도 실제 식당 메뉴 우선 추첨으로 완전히 전환하기 전까지 메뉴 카탈로그의 데모 후보를 사용할 수 있다. 응답의 `menu_catalog_demo` 표시는 이 차이를 구분한다.
