# LunchRun 챗봇 추천 정책 v3

- 작성일: 2026-11-10
- 상태: 5단계 DB 실행 연결 버전
- 이전 버전: `chatbot_policy_v2.md`
- 코드에는 이 버전의 DB 사실 조회 원칙을 적용한다.

## 1. v2에서 달라진 점

- `services.py`의 임시 메뉴 배열을 제거했다.
- 메뉴 후보와 설명은 SQLAlchemy의 `menu_catalog`에서 읽는다.
- 주변 식당에 확인된 실제 메뉴·가격이 있으면 카탈로그 후보보다 우선한다.
- 메뉴 추천과 식당 검색을 분리하여 메뉴 재추천만으로 카카오 검색을 실행하지 않는다.
- 식당 가격·주소·메뉴·영업상태·추천 이유 후속 질문을 실제 DB에 연결한다.

## 2. 메뉴 선정 정책

1. 현재 위치와 반경 안에서 상세 수집에 성공한 식당 메뉴를 찾는다.
2. 실제 메뉴 가격이 예산 이내이고 대표 메뉴 또는 별칭과 일치하면 DB 근거 후보로 사용한다.
3. 실제 근거가 없을 때만 활성 메뉴 카탈로그와 `price_hint`로 후보를 만든다.
4. `price_hint`는 식당의 실제 가격으로 출력하지 않는다.
5. 재추천은 현재 메뉴와 세션의 최근 메뉴를 제외한다.
6. 후보가 없으면 고정 메뉴로 보완하지 않고 조건 변경을 안내한다.

## 3. 식당 검색 정책

- 화면 표시명과 카카오 검색어를 분리하고 `menu_catalog.search_keyword`를 사용한다.
- 검색 결과는 카카오 ID를 PK로 `restaurant`에 추가 또는 갱신한다.
- 저장된 상세정보를 우선 사용하고 필요한 후보만 상세 수집 대상으로 보낸다.
- 대표 메뉴명뿐 아니라 메뉴 별칭도 실제 수집 메뉴와 비교한다.
- 메뉴 판매, 예산, 현재 한국 시간 기준 영업 여부를 모두 확인한 식당만 추천 목록에 둔다.

## 4. 질문별 실행

| 의도 | 서버 동작 |
|---|---|
| `recommend_menu` | DB 조건 후보에서 메뉴만 선정하며 식당 검색은 하지 않음 |
| `reroll_menu` | 최근 메뉴를 제외해 다시 선정하며 식당 검색은 하지 않음 |
| `search_restaurants` | 선택 메뉴가 있으면 사용하고 없으면 먼저 메뉴를 선정한 후 식당 검색 |
| `ask_menu_detail` | `menu_catalog.description`으로 답변 |
| `ask_restaurant_detail` | 최근 추천 식당의 DB 정보로 답변 |

## 5. 식당 후속 질문

### 가격

- 현재 선택 메뉴의 대표명과 별칭으로 수집 메뉴를 찾는다.
- 확인 가격이 여러 개면 가장 낮은 확인 가격을 표시한다.
- 현재 예산 이내인지 함께 알린다.
- 확인 가격이 없으면 `가격 확인 불가`를 표시한다.

### 영업 여부

- `hours_status=success`인 경우만 계산한다.
- 요청 시점의 한국 시간과 요일별 영업 구간을 비교한다.
- 브레이크 타임과 익일 종료 구간을 구분한다.
- 영업 구간에 포함되지만 휴무 여부가 NULL이면 `휴무일 확인 필요`를 함께 표시한다.
- 영업시간을 확인하지 못했으면 `현재 영업 상태를 알 수 없습니다`라고 표시한다.

### 주소와 메뉴

- 주소는 `restaurant.address`만 사용한다.
- 메뉴는 상세페이지에서 수집된 `menu` 행만 표시한다.
- 메뉴 수집이 성공하지 않았거나 행이 없으면 `메뉴 확인 불가`를 표시한다.

### 추천 이유

다음 중 DB에서 확인된 근거만 조합한다.

- 선택 메뉴 판매 확인
- 확인 가격이 예산 이내
- 수집된 영업시간 기준 현재 영업 중

## 6. 사실 정보 안전 규칙

- Groq는 질문 의도와 최근 식당 대상을 해석할 뿐 가격·주소·영업 여부를 작성하지 않는다.
- 후속 답변은 SQLAlchemy 조회값으로 서버가 직접 구성한다.
- 누락값을 0원, 임의 주소 또는 영업 중으로 바꾸지 않는다.
- 최근 추천 목록 밖의 식당 ID는 4단계 Pydantic 가드레일에서 거부한다.
- 후속 질문은 카카오 검색이나 상세페이지 재수집을 다시 시작하지 않는다.

## 7. 현재 제한

- 채식, 맵기, 알레르기, 할랄과 총소요시간은 아직 검증하지 않는다.
- 초기 10개 대표 메뉴의 시드 원본은 `database/seed.py`에 있지만, 실행 중 추천과 Groq 허용 목록은 이 배열이 아니라 DB 행을 조회한다. 이후 관리자 기능이나 마이그레이션으로 DB 메뉴를 확장할 수 있다.
- 상세페이지 추가 수집을 기다리는 스트리밍 진행 메시지와 스피너 개선은 다음 단계 범위다.
- 개발 세션은 메모리 방식이므로 서버 재시작 시 대화 문맥이 사라진다.
