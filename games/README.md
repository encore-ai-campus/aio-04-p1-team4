# LunchRun 데모 3 · 우리의 교집합

데모 2를 보존하고 별도로 만든 모임방 버전입니다. 실제 방·닉네임 참여·각자 선택·교집합·최다 선택 후보 재투표·최종 메뉴 공유를 서버에 저장합니다.

## 실행

Node.js와 Python이 설치된 환경에서 `python -m pip install -r requirements.txt`로 QR 패키지를 설치하고 `node server.mjs`를 실행합니다. PC에서는 http://127.0.0.1:4174 를 엽니다. 시작 로그에 같은 네트워크 휴대폰용 주소도 표시됩니다. 기본 서버는 다른 기기 참여를 위해 0.0.0.0:4174에서 수신합니다. 루프백으로 제한하려면 HOST=127.0.0.1을 지정합니다.

## 백엔드 FastAPI에서 `/games`로 제공

`app.main:app`의 `/games` 경로는 게임 요청을 Node.js 앱으로 전달합니다. 두 서버를 별도 터미널에서 실행하고 http://127.0.0.1:8000/games/ 에 접속하세요. FastAPI는 기본적으로 8000 포트, Node.js는 내부 연결용 4174 포트를 사용합니다. `/games`도 `/games/`로 자동 이동합니다. `games/app.py`는 기존처럼 독립 FastAPI 프록시로도 실행할 수 있으며, 이 경우 `/game/`을 사용합니다.

LunchRun 메인 화면에서 게임으로 이동하면 예산, 남은 시간, 거리, 인원, 카테고리와 현재 위치가 같은 브라우저 탭의 세션 저장소로 전달됩니다. 게임의 메뉴 후보와 모임방은 이 값을 사용하며, 위치 좌표는 주소에 포함되지 않습니다.

PowerShell 터미널 1:

```powershell
python -m pip install -r requirements.txt
$env:HOST = "127.0.0.1"
$env:PORT = "4174"
node server.mjs
```

PowerShell 터미널 2:

```powershell
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

로컬 PC에서만 접속할 때는 `127.0.0.1`을 사용하세요. 휴대폰에서도 접속하려면 `--host 0.0.0.0`으로 실행하되, `0.0.0.0` 자체는 접속 주소가 아닙니다. 휴대폰 브라우저에는 PC의 실제 로컬 네트워크 IP와 `/games/` 경로를 사용하세요(예: `http://192.168.0.10:8000/games/`). PC와 휴대폰은 같은 Wi-Fi에 연결되어야 하며 방화벽에서 8000 포트를 허용해야 할 수 있습니다. 게임의 방 API와 정적 자원 역시 FastAPI 경로를 통해 프록시됩니다. FastAPI를 외부 프록시 뒤에서 운영하는 경우 외부에서 접근 가능한 도메인과 HTTPS 프록시 설정을 함께 구성하세요.

서버가 PC에서 실행 중이어야 합니다. 휴대폰은 같은 Wi-Fi에 연결하고 모임방의 QR·초대 링크를 엽니다. 공유기 기기 격리·게스트 Wi-Fi·Windows 방화벽이 연결을 막으면 네트워크 설정에서 허용 여부를 확인해야 합니다. 이 구현은 공용 인터넷 배포나 터널을 만들지 않습니다. 모바일 데이터·외부 네트워크 접근은 지원하지 않습니다.

QR은 Python reportlab의 QR 생성기를 사용합니다. 지정된 번들 Python이 있으면 우선 사용하고, 없으면 `python`을 찾습니다. 다른 경로가 필요하면 `PYTHON_BIN`을 지정하세요. QR 생성에 실패해도 링크와 6자리 방 코드로 참여할 수 있습니다. PUBLIC_URL을 지정하면 초대 주소를 해당 origin으로 생성합니다.

유선·Wi-Fi 전환 시 현재 PC 주소를 다시 확인해 QR과 초대 링크를 갱신합니다. 이미 열린 대기실도 다음 연결 확인 때 갱신합니다. 휴대폰에서 이전 주소로 열어 둔 페이지는 PC 화면의 새 QR로 다시 접속하세요. PUBLIC_URL을 지정한 경우에는 해당 고정 주소를 우선 사용합니다.

## 시연

1. 함께 골라요 → 우리의 교집합. 방장 닉네임으로 방 만들기.
2. 휴대폰 또는 다른 브라우저 탭에서 QR·링크·코드로 참여. 회원 로그인은 필요 없습니다.
   QR·초대 링크의 방 번호를 읽으면 닉네임 참여 화면이 바로 표시됩니다. 닉네임을 입력하고 참여하면 해당 방 대기실로 이동하며, 같은 탭에서 새로고침하면 참여 상태를 복구합니다. 여러 사람이 같은 QR을 사용할 수 있습니다.
3. 2명 이상 모이면 방장이 시작. 시작 후 새 참여는 차단하고 후보·참여자를 고정합니다.
4. 각자 먹고 싶은 메뉴를 여러 개 골라 제출. 다른 사람에게는 제출 여부만 보입니다.
5. 전원 제출 후 교집합을 표시합니다. 여러 후보는 방장이 룰렛으로, 하나면 해당 메뉴로 결정합니다.
6. 교집합이 없으면 방장이 최다 선택 후보로 다시 고르기를 눌러 전원이 다시 선택합니다. 동점 최다 후보는 모두 포함합니다.
7. 최종 결정은 모든 기기에 공유됩니다. 각자 식당 찾기로 이동해 기존 CSV 식당 추첨·예상 동선 화면을 이용합니다.

참여자는 최대 12명, 방 수명은 24시간입니다. 방과 선택은 data/rooms.json에 원자적으로 저장합니다. 이 파일에는 참여 자격 토큰이 있으므로 공개하거나 정적 폴더에 두지 마세요. 새로고침 복구용 토큰은 각 브라우저 탭의 sessionStorage에 저장합니다. 방장 권한은 QR/초대 링크에 포함되지 않습니다.

참가자가 나갔거나 연결을 잃어 진행이 막히면 방장이 대기실로 되돌려 참여자를 정리한 뒤 다시 시작합니다. 다시 시작하면 기존 선택은 초기화됩니다. 같은 브라우저를 다른 사람과 공유하면 해당 탭의 참가자 자격을 함께 사용하게 되므로 실제 시연은 별도 탭·프로필·휴대폰을 사용하세요.

현재 메뉴는 기존 금천구 CSV를 점심 조건으로 필터링한 결과에서 최대 20개 대표 후보를 준비합니다. 사진이 없으므로 음식 이모지는 장식 예시이며 실제 음식 사진이 아닙니다. 생성형 AI·실제 지도 API·회원 인증은 새로 연결하지 않았습니다. 서버가 저장한 상태를 약 1.1초 간격으로 확인합니다.

## 게임 화면 디자인과 코드 구성

`/games/`는 기존 메인 화면의 흰 배경, 주황색 게임 카드, 오른쪽 진행 메뉴를 사용합니다. 기본 화면은 게임 선택 화면이며, 게임 카드를 누르면 `#play`의 플레이 전용 화면으로 이동합니다. 오른쪽 `GAME or AI` 버튼 또는 브라우저 뒤로가기로 선택 화면에 돌아올 수 있습니다. 함께 고르기·AI·모임방은 추천 방식 탭에서 선택합니다. 오른쪽 `조건 설정` 버튼은 메인 홈으로 이동하고, 헤더의 `위치 · 조건`은 조건 팝업을 엽니다. 인원을 변경하면 1명은 혼자 고르기, 2명 이상은 함께 고르기로 자동 전환합니다. 로고는 메인 홈(`/`)으로 이동합니다. 모바일에서는 진행 메뉴가 화면 아래에 표시됩니다.

- `dist/index.html`: 헤더, 조건 팝업, 게임 영역, 진행 메뉴
- `dist/minimal-ui.css`: 화면 배치와 반응형 디자인
- `dist/app.mjs`: 게임 동작, 조건 상태, 화면 전환
- `dist/rooms.mjs`: 모임방 참여와 투표
- `dist/assets/`: 메인 화면과 같은 로고·게임 이미지

`dist/assets/gacha-machine.png`는 플레이 화면 전용 이미지로, 기존 가챠 이미지의 오른쪽 반짝이를 제거하고 본체를 중앙에 배치했습니다. 선택 카드용 원본 이미지는 별도로 유지합니다.

JavaScript, HTML, CSS는 들여쓰기와 줄바꿈을 정리했으며, HTML 템플릿에는 `/* HTML */` 표시를 추가해 편집기와 포매터에서 읽기 쉽게 유지합니다. CSV 데이터가 포함된 `engine.mjs`는 별도로 유지합니다.

## 검증

`node --test room-store.test.mjs`로 권한·선택 비공개·교집합·최다 동점 재투표·고정 룰렛 결과·재시작 복구·정원·만료·오래된 라운드 거절을 확인합니다. 실제 휴대폰의 네트워크 연결은 해당 Wi-Fi·방화벽 환경에서 별도로 확인해야 합니다.
